# Обновление заявок и ручное добавление релизов

## Установка

1. В SQL Editor существующего проекта Supabase выполните весь файл `supabase/migrations/20261004174646_unified_demo_and_manual_releases.sql`. Он рассчитан на уже установленные миграции платформы, команды и demo_release_flow. Изменения выполняются одной транзакцией. Повторно выполнять файл не нужно.
2. После успешного SQL обновите приложение на Vercel из локальных изменений проекта. Новые переменные окружения не нужны. До применения SQL новая версия кабинетов не должна разворачиваться.
3. Попросите артиста подтвердить email и войти в кабинет. Email должен совпадать с указанным в демо (регистр букв не важен). Если использован другой email, автоматическая привязка не выполняется.

## Заявки

- Новые демо с лендинга автоматически связываются с аккаунтом с подтверждённым email.
- Старые непривязанные демо связываются при выполнении миграции.
- Если артист зарегистрировался позже, вход в кабинет связывает его ранее отправленные демо. Повторный вход не создаёт дубликатов.
- Уже назначенные другому аккаунту заявки не переназначаются. Совпадение псевдонима не используется для доступа.
- Подтверждение email доказывает принадлежность почтового ящика аккаунту, но публичная форма сама по себе не подтверждает личность отправителя демо.

## Релизы вне платформы

1. Артист должен зарегистрироваться, подтвердить email и войти хотя бы один раз.
2. В кабинете лейбла откройте Release queue → Add release. Также ссылка Add release есть в списке Artists.
3. Выберите аккаунт по имени и email. Заполните метаданные, треки, кредиты, ссылки WAV/FLAC и обложку.
4. Save draft сразу создаёт релиз в кабинете выбранного артиста и его команды, а также в очереди лейбла. Для его создания одобренное демо не требуется.
5. Артист, редакторы его команды и лейбл могут дополнять этот черновик. Отправка и дальнейшие статусы используют существующую процедуру проверки, одобрения и доставки.
6. Для архивного релиза лейбл может указать прошедшую дату. Обычные заявки артистов сохраняют требование будущей даты.

## Проверки

`npm run test:platform` проверяет SQL и RLS в изолированной PostgreSQL базе PGlite: публичные заявки, подтверждение email, повторную привязку, изоляцию аккаунтов, ограничения лейбла, создание/редактирование релиза, загрузку обложки и статусы.

Рабочая база и развёртывание не менялись в рамках локальной доработки.
